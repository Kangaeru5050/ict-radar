ICT BASIC FITNESS / NETWORK

← もっと知りたい

ネットワークの
基礎体力

用語を暗記する前に、「端末からサービスまで、通信がどこを通っているか」を一本の地図として理解します。基礎は安定して学び、変わる情報はCURRENTとして別に更新します。

最初の原則「つながっている」と「使える」は違う。

01 / BIG PICTURE

まず、学校ネットワークの全体像を見る

図から入る

学校のネットワークは自治体によって構成が違います。最初に「ネットワーク分離」と「アクセス制御」という2つの考え方を見比べ、そのあと自分の自治体を7つの質問で読み解きます。

ここでつかむこと

ネットワーク分離は「ネットワークを分ける」考え方、ゼロトラストは場所だけを信頼せずアクセスごとに確認する考え方です。SASEやMDMはゼロトラストそのものではありません。

目標

7つに答えられれば、知らない自治体でもネットワーク構成を自分の言葉で説明するための入口ができます。

MEET THE NETWORK

次に、通信を支える「登場人物」を知る

「AP」「DHCP」「DNS」といった言葉は、最初から覚えていなくて大丈夫です。まずは、それぞれが何をする係なのか、そこで問題が起きると何ができなくなるのかを見てみましょう。

💻
START

端末

PC・タブレット

何をする？利用者が通信を始める場所です。Wi-Fi設定やネットワーク設定を持っています。

ここで問題があるとその端末だけつながらない、という形になりやすい。

📶
ENTRANCE

AP

アクセスポイント

何をする？端末をWi-Fiで校内ネットワークへつなぐ「無線の入口」です。

ここで問題があるとWi-Fiにつながらない、特定の教室だけ不安定、などが起こります。

🏷️
SETTING

DHCP

通信設定を渡す仕組み

何をする？IPアドレス、ゲートウェイ、DNSなど、通信に必要な設定を端末へ自動で渡します。

ここで問題があるとWi-Fiには接続したように見えても、正しく通信できないことがあります。

🔀
INSIDE SCHOOL

スイッチ / LAN

校内をつなぐ

何をする？校内の端末やAPなどをつなぎ、LANの中で通信を中継します。

ここで問題があると特定の教室・フロア・系統だけ通信できないことがあります。

🚪
EXIT

ルーター / ゲートウェイ

別のネットワークへの出口

何をする？校内LANから別のネットワークへ通信を渡します。

ここで問題があると校内では通信できても、外部や別ネットワークへ進めません。

🔎
FIND

DNS

名前から通信先を探す

何をする？Webサイトなどの名前を、通信に使うIPアドレスへ結びつけます。

ここで問題があると回線自体は動いていても、名前を使ってWebサイトを開けないことがあります。

🌐
ROUTE

インターネット / 閉域網

通信先までの経路

何をする？クラウドや教育委員会など、校外の通信先までデータを運びます。

ここで問題があると校内ネットワークは正常でも、外のサービスへ届きません。

☁️
DESTINATION

クラウドサービス

使いたいサービス

何をする？学習アプリ、校務支援、Webサービスなど、利用者が最終的に使いたい機能を提供します。

ここで問題があるとインターネットは使えるのに、特定のサービスだけ使えないことがあります。

🔐
IDENTITY & PERMISSION

IdP・認証・認可

誰？ 何をしてよい？

何をする？認証で「誰か」を確認し、認可で「何をしてよいか」を決めます。SSOやMFAもここに関係します。

ここで問題があるとサービスには届いているのにログインできない、ログイン後に必要な機能が使えないことがあります。

CHECKPOINTS

「通信の順番」ではなく、「どこまで正常か」を確かめる

実際の通信は、DNSや認証などが単純に一直線の順番で並ぶわけではありません。切り分けでは、次のような確認ポイントとして考えると分かりやすくなります。

① 端末→② Wi-Fi / AP→③ IP設定→④ 校内LAN→⑤ 外への経路→⑥ 名前解決→⑦ サービス→⑧ 認証・権限
たとえば「Wi-Fiマークは出ているのに、Webサイトが開かない」

分かること少なくとも、端末とAPの無線接続はできている可能性があります。

まだ分からないことIP設定、校内LAN、外への経路、DNS、サービス側などが正常とは限りません。

次の一手「Wi-Fiがつながっているからネットワークは正常」と決めず、どこまで正常かを一つずつ確認します。

02 / FOUNDATION

用語を、もう少し正確に理解する

FOUNDATION

上の「登場人物」で役割をつかんだら、ここで技術用語として少し正確にします。試験のための暗記ではなく、現象を説明し、切り分けるための基礎です。

01

IPアドレス

ネットワーク上で通信相手を識別するためのアドレス。IPv4とIPv6があります。

問い：この端末は通信に必要なアドレスを持っている？
02

DHCP

IPアドレスなど、通信に必要な設定を端末へ提供する仕組み。

問い：端末は適切なネットワーク設定を受け取れた？
03

DNS

人が使う名前から、通信先を見つけるための仕組み。

問い：名前から通信先を解決できている？
04

デフォルトゲートウェイ

自分のネットワークの外へ通信するときの出口。

問い：外へ出る経路はある？
05

アクセスポイント

無線端末をネットワークへ接続する入口。電波の届き方だけでなく同時接続や配置も関係します。

問い：無線区間だけの問題？
06

ルーター / スイッチ

ルーターは異なるネットワーク間、スイッチは主に同一LAN内の通信をつなぎます。

問い：どの区間まで通信できている？
07

帯域と遅延

一度に運べる量と、応答にかかる時間は別の性質です。「遅い」の中身を分けます。

問い：足りないのは容量？応答性？
08

HTTPS

Web通信を保護する仕組み。ただし、通信先の内容が正しいことや、入力してよい情報まで保証するものではありません。

問い：通信の安全と情報の妥当性を混同していない？

03 / TRAINING LADDER

用語から、切り分けへ

KNOW → HANDOFF

ネットワークは用語暗記だけでは現場で使えません。「分かる」から「原因範囲を絞り、適切につなぐ」までを4段階で見ます。

Lv1

KNOW

知っている

IP、DHCP、DNS、AP、ルーター等の役割を説明できる。

例DNSは何をする？ DHCPは端末へ何を渡す？
Lv2

DISTINGUISH

区別できる

似た状態や機器の役割を一括りにしない。

例Wi-Fi≠インターネット、AP≠ルーター、帯域≠遅延、DNS障害≠通信断。
Lv3

DIAGNOSE

切り分けられる

正常・異常を比較し、端末・無線・LAN・DNS・サービス等のどこまで正常かを絞る。

例「誰に・どこで・何が・いつから」を集め、一つずつ条件を変えて確認する。
Lv4

SUPPORT / HANDOFF

学習を止めずにつなげる

権限境界を守り、確認済み情報と再現条件をそろえて担当者へ渡す。

例勝手に設定変更せず、代替手段・影響範囲・端末情報・時刻・ログ等を整理する。

04 / DIAGNOSE

「ネットが遅い」を分解する

学校ICTの実践

いきなり設定を変えるのではなく、観察して影響範囲を絞ります。

1

誰に？

自分だけ / 複数人 / 全員

2

どこで？

この席 / 教室 / 校舎 / 学校全体

3

何が？

特定サイト / 全Web / ログイン / 動画 / 全通信

4

いつから？

常時 / 特定時間 / 変更後 / 今日だけ

BEFORE ACT

原因らしい場所が見えても、すぐ変更しない。

「私は、この環境で、これを変更する権限を持っているか？」を確認します。技術的に変更できることと、変更してよいことは別です。

05 / CURRENT WATCH

ネットワークの「今」

CURRENT

規格、国の調査、学校向けの整備指針は変わります。ここは基礎知識と混ぜず、一次情報を確認して更新します。

確認情報を読み込んでいます…

更新ルール

FOUNDATION は概念が変わらない限り維持。CURRENT は文部科学省などの一次情報とIETF等の標準を定期確認し、「確認日」を表示します。新しい情報を自動で見つけても、意味づけは確認してから掲載します。
