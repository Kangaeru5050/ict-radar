ネットワークの
基礎体力

用語を暗記する前に、「端末からサービスまで、通信がどこを通っているか」を一本の地図として理解します。基礎は安定して学び、変わる情報はCURRENTとして別に更新します。

最初の原則「つながっている」と「使える」は違う。

01 / BIG PICTURE

まず、学校ネットワークの全体像を見る

図から入る

学校のネットワークは自治体によって構成が違います。最初に「ネットワーク分離」と「アクセス制御」という2つの考え方を見比べ、そのあと自分の自治体を7つの質問で読み解きます。

図解 1

学校ICTのネットワークの考え方とつながり方

どちらが優れているかではなく、自分の自治体がどの構成かを理解するための地図です。

1

ネットワーク分離モデル

従来型・三層分離の例

校務系・学習系・インターネット系を物理的・論理的に分けて運用します。

校務系校務端末 → 校務系FW → 閉域網／無害化通信原則、一般インターネットへ直接接続しない構成
学習系学習端末 → 学習系FW → 学習用クラウド
インターネット系閲覧用端末 → インターネット系FW → Web
見るポイントどのネットワークにいる？外へ出る経路は？校務データはどう受け渡す？
2

ゼロトラスト（アクセス制御）モデル

クラウド活用型の例

場所だけを信頼せず、「だれが・どの端末で・何にアクセスするか」を確認して必要なアクセスだけを許可します。

利用者・端末学校・自宅・出張先
→
IdPSSO / MFA / リスク確認
→
SASE等アクセス制御 / URL制御 / ログ
→
クラウド校務 / 学習 / その他
見るポイント認証基盤は？端末の管理・認証は？ログはどこへ集まる？
混同しないゼロトラストは考え方、SASEは実現手段の一つ、MDMは端末管理の仕組みです。実際の自治体には移行途中や複合構成もあります。
図解 2

初めて行く自治体でも読める「7つの質問」

製品名を覚えるより、通信・認証・端末・権限・記録の流れをたどります。

1

通信はどこを通る？

校内FW？ 教委/DC？ SASE？ ローカルブレイクアウト？

2

だれだと確認する？

IdP、SSO、MFA、リスクベース認証はどこで行う？

3

どの端末なら使える？

管理対象端末？ MDM/EMM？ 端末認証？ OSや設定の状態は？

4

どのサービスに入れる？

学習系SaaS、校務支援、一般サービスで権限はどう違う？

5

Webアクセスはどこで制御する？

URLフィルタリングは校内FW？ クラウド型ゲートウェイ？

6

何が記録・監視される？

アクセスログ、端末ログ、異常検知、SIEM等はどこにある？

7

障害時はどこまで正常？

端末 → Wi-Fi → LAN → DNS → 認証 → サービスの順に境界を探す。

7つに答えられれば

知らない自治体でも「どこを通り、誰と端末をどう確認し、何にアクセスし、何を記録しているか」を自分の言葉で説明できます。

COMMUNICATION PATH

次に、1本の通信をたどる

Webサイトやクラウドが使えるまでには、いくつもの段階があります。「ネットがダメ」で一括りにしないことが、切り分けの出発点です。

端末PC / tablet
→
Wi-FiAPへ接続
→
IP設定DHCP等
→
校内LANswitch / router
→
インターネット回線 / ISP
→
DNS名前解決
→
サービスWeb / cloud
→
認証・認可誰？何ができる？
重要な区別

Wi-Fiマークが出ている → APとは接続できている可能性がある。
だからといって、DNS・インターネット・クラウドサービス・認証まで正常とは限りません。

02 / FOUNDATION

ここは変わりにくい基礎

FOUNDATION

試験のための単語集ではなく、現象を説明し、切り分けるために必要な概念です。

01

IPアドレス

ネットワーク上で通信相手を識別するためのアドレス。IPv4とIPv6があります。

問い：この端末は通信に必要なアドレスを持っている？
02

DHCP

IPアドレスなど、通信に必要な設定を端末へ提供する仕組み。

問い：端末は適切なネットワーク設定を受け取れた？
03

DNS

人が使う名前から、通信先を見つけるための仕組み。

問い：名前から通信先を解決できている？
04

デフォルトゲートウェイ

自分のネットワークの外へ通信するときの出口。

問い：外へ出る経路はある？
05

アクセスポイント

無線端末をネットワークへ接続する入口。電波の届き方だけでなく同時接続や配置も関係します。

問い：無線区間だけの問題？
06

ルーター / スイッチ

ルーターは異なるネットワーク間、スイッチは主に同一LAN内の通信をつなぎます。

問い：どの区間まで通信できている？
07

帯域と遅延

一度に運べる量と、応答にかかる時間は別の性質です。「遅い」の中身を分けます。

問い：足りないのは容量？応答性？
08

HTTPS

Web通信を保護する仕組み。ただし、通信先の内容が正しいことや、入力してよい情報まで保証するものではありません。

問い：通信の安全と情報の妥当性を混同していない？

03 / TRAINING LADDER

用語から、切り分けへ

KNOW → HANDOFF

ネットワークは用語暗記だけでは現場で使えません。「分かる」から「原因範囲を絞り、適切につなぐ」までを4段階で見ます。

Lv1

KNOW

知っている

IP、DHCP、DNS、AP、ルーター等の役割を説明できる。

例DNSは何をする？ DHCPは端末へ何を渡す？
Lv2

DISTINGUISH

区別できる

似た状態や機器の役割を一括りにしない。

例Wi-Fi≠インターネット、AP≠ルーター、帯域≠遅延、DNS障害≠通信断。
Lv3

DIAGNOSE

切り分けられる

正常・異常を比較し、端末・無線・LAN・DNS・サービス等のどこまで正常かを絞る。

例「誰に・どこで・何が・いつから」を集め、一つずつ条件を変えて確認する。
Lv4

SUPPORT / HANDOFF

学習を止めずにつなげる

権限境界を守り、確認済み情報と再現条件をそろえて担当者へ渡す。

例勝手に設定変更せず、代替手段・影響範囲・端末情報・時刻・ログ等を整理する。

04 / DIAGNOSE

「ネットが遅い」を分解する

学校ICTの実践

いきなり設定を変えるのではなく、観察して影響範囲を絞ります。

1

誰に？

自分だけ / 複数人 / 全員

2

どこで？

この席 / 教室 / 校舎 / 学校全体

3

何が？

特定サイト / 全Web / ログイン / 動画 / 全通信

4

いつから？

常時 / 特定時間 / 変更後 / 今日だけ

BEFORE ACT

原因らしい場所が見えても、すぐ変更しない。

「私は、この環境で、これを変更する権限を持っているか？」を確認します。技術的に変更できることと、変更してよいことは別です。

05 / CURRENT WATCH

ネットワークの「今」

CURRENT

規格、国の調査、学校向けの整備指針は変わります。ここは基礎知識と混ぜず、一次情報を確認して更新します。

確認情報を読み込んでいます…

更新ルール

FOUNDATION は概念が変わらない限り維持。CURRENT は文部科学省などの一次情報とIETF等の標準を定期確認し、「確認日」を表示します。新しい情報を自動で見つけても、意味づけは確認してから掲載します。
